## Mount and navigation

Import `PortraitPanel` from `components/portrait/PortraitPanel.tsx` and the types from `lib/portrait/contracts.ts`. Mount only within the authorized hidden preview until editorial release. Props:

- `scene?: {place?, volumeId?, sectionId?, returnMarker?}`. `volumeId` is the actual `Volume.slug`; `sectionId` is the real `Leaf.key`. Supply the already-authorized current book, not an arbitrary guessed project slug.
- `onNavigate(intent, signal): Promise<"success" | "cancelled" | "unavailable">`. The unchanged intent has `intentId`, `turnId`, `targetId`, `mode` (`focus|book|report`), optional `sectionId`, and `label`. Use the shared route/history layer and A's actual section helper; preserve book/return markers, release pointer lock, honor reduced motion and check the AbortSignal before moving or acknowledging. No raw URLs, cameras or model-approved flags exist.
- `onCancelMedia?()` pauses existing custodian/film before a turn. This panel is text-only; it generates no speech. Keep `useCustodian` as the only speaker.
- `onClose?()` removes the panel. Closing aborts generation/navigation. `cancelKey?` changes for **external** media starts or route changes; do not bump it for the navigation currently being acknowledged, or the panel correctly cancels its own pending acknowledgement.

The panel calls the server to reauthorize and consume each signed navigation before invoking the callback. Only a server-recognized explicit show/open/take request auto-invokes it; other questions offer a button. Duplicate, old-turn, forged and cancelled actions cannot execute. The UI says “Opened” only after callback success. Plain fallback uses the same callback to map known target/section IDs to the existing reading/report UI. The coordinator must not use a model's prose as a route. Source links are server-owned HTTPS records; internal cards expose actual volume/leaf IDs.

The panel is a scrollable complementary region, not a modal or focus trap. Native buttons, textarea, source details, Escape/Stop, narrow layout and silent authored reflections work without a canvas. Browser keyboard/narrow-screen/Back/acknowledgement qualification remains with integration.

## Server and scope

`POST /api/portrait` accepts strictly bounded `turn`, `sources`, `navigate` and `cancel` bodies. Preview flags, assistant history, arbitrary citations on a turn, tools, URLs and other unknown properties are rejected. It checks `getAdmin()` on every projection and excludes password-change-only accounts. `getCollection`'s loopback starter exception is rejected for anonymous viewers: `source: review` is accepted only with actual admin authorization. Public normal collections use the existing visibility and redaction projection. An unlisted volume enters only from an explicit validated direct current-volume context; alias search does not add it. Publication and ingestion activation follow the existing catalog policy; no invented tracking gate is added.

Current project prose comes from projected `Volume.pages`, hashes its current text for revision IDs, and resolves project aliases through `projectSlug`, never presumed book-slug equality. No repository, client payload, environment, raw history, old assistant answer or generated summary is indexed. Each source inspection and action is reprojected; the response rechecks revisions after provider latency. No answer cache exists. The UI replaces the previous answer on a new turn, retains only an authorized context identifier, and stores no chat in localStorage.

All new historical/briefing cards remain `reviewed-draft`, authenticated preview only. Private projected projects are labeled `curated-project-draft`; only the existing released public projection is labeled `owner-approved`. Neither label approves the new narration. Implementation/deployment/commercial claims remain distinct in excerpts and source cards.

## Durable storage, migration and operations

The coordinator integrated the documented `PortraitLedger` model and additive migration `prisma/migrations/20261113010000_portrait_ledger/migration.sql`. The source design copies remain in `lib/portrait/`. Nothing has been applied to the owner's database. `tests/portrait.test.ts` is included in `npm test`; no dependency was added. Final production-mode disposable database evidence is recorded in [the integration record](SESSION_INTEGRATION.md).

Paid and remote runtime use the existing Prisma database, a transaction and `SELECT ... FOR UPDATE` on singleton `portrait_ledger`. The global row serializes admission, budget reservation, per-session/network limits and settlement across instances. A reservation prices the entire 8,000-input/450-output call as uncached. Only validated reported usage releases unused money; missing usage, timeout, disconnect, malformed provider response or accounting outage holds the reservation. Idempotency never redispatches a duplicate. An over-reservation reported charge kills admission for operator reconciliation. Unresolved reservations count against future days/months too, preventing a midnight refund loophole.

The **development exact loopback office mock only** uses an OS `mkdir` lock and atomic rename in `os.tmpdir()/overton-portrait-mock-<checkout hash>`. Its zero-dollar ledger and signing key persist across server instances/restarts. Paid code can never select that store. A stale lock fails closed; an operator may remove the exact lock directory after confirming the server process stopped, never during a running request. Do not restart the owner's current office for this task. Remote SQL absence fails closed; no in-memory production fallback exists.

Use SQL transaction + row lock for an operator reconciliation, inspect the unresolved charge ID/model/price, and settle only against confirmed provider usage. Do not clear the ledger to get past a cap. For a planned schema migration, preserve pending charges. The single-row JSON ledger favors correctness for this small private portfolio; growing traffic should migrate to normalized reservations while retaining the same atomic invariant.
